| M1 的 projectionSchema 方案 | 作为候选方案保留 | 可比较共享的纯 schema/规范化契约或由节点适配器产出带版本的期望/观测投影。spec §27 对必要共享 schema/validation 留有例外；无需把 Agent 专属路径塞进控制器 |
| M3：快照/工件保留与 generation 唯一性 | 采纳；限定 MVP 保证 | 明确立即上一成功状态的可恢复引用及回收保护；旧快照不可用时显式拒绝。无需无限保留所有历史。分离内容寻址与每机 generation 记录，覆盖 A→B→A |

| S3：enrollment TLS 与限速 | TLS 矛盾必须修；限速阈值是设计决策 | 架构 RD-2 的“HTTP/2 明文路径”与 §7.5 的 HTTPS 及引导 CA 校验冲突。无客户端证书不等于明文传输；一次性 token 不能替代服务端认证与加密 |

## 5. 后续修订的验收原则

以下是下一轮架构修订的验收条件，不是本轮已通过的测试：

1. 同一目标在 daemon 与 SSH 并发、控制面重启、超时后迟到等场景下，不会发生交错变更或旧结果覆盖新状态。
2. 空计划也不能跳过必要健康验证后直接宣告成功；操作成功和 Deployment 门禁绑定同一机器、操作、快照及有效观测。
3. 任一变更后失败或崩溃，都有明确恢复路径；回滚恢复上一成功受管状态，同时保留当前未托管字段；无法安全恢复时明确 Degraded。
4. 摘要规范有固定 fixture，未托管字段编辑不产生 drift，受管内容修改必须产生 drift；A→B→A 与跨机不同 generation 仍能确定 Deployment 目标。
5. Skill 工件的完整性、路径边界及资源上界独立成立；摘要匹配不能替代路径安全，也不能只看 symlink 名称判断内容未变。
6. enrollment、续期、Hello 身份有一致绑定；日志、operation 与 observed-state 的数据边界能满足不泄露 secrets 的验收。
7. 文档使用同一套术语、摘要定义、状态写入方与错误语义；容量目标保留为需验证目标。

以上是本轮汇总后的后续验收建议；第二轮原始发现和必要的再校正如下。

| plan 与 apply 间变化 | A6 | 采纳确认语义缺口；原文已有完整流水线，不能说完全没有重算计划 | 锁内重取观测并重算；如产品承诺确认具体 plan，验证目标与计划基线，变化则要求重新确认；不因未托管编辑丢弃用户内容 |

| A→B→A 与历史引用 | F6 | 采纳；两张表不是唯一解 | 明确每机 generation 与内容 digest 的关系；A→B→A 生成可引用的新代，保留回滚目标。可使用按 generation 唯一、digest 普通索引的单表，是否拆表按需求决定 |

### 对第二轮建议的必要修正

1. **不能用 `reportedAt > op.finishedAt` 代替因果绑定。** spec 的健康检查、重新 inventory、verify 位于成功提交之前；严格要求这些步骤晚于操作结束会拒绝正常执行。服务端接收时间也不能证明采集时间，迟到旧报文照样晚到。应将同一操作产生的验证证据与结果绑定，区分“变更完成”与“操作最终提交”，并校验顺序/身份。
2. **节点单 worker 不等于跨进程互斥。** daemon 队列无法单独阻止 SSH 启动的另一个 oneshot 进程；持久化控制面占位也不能让节点上的失联旧进程停止。必须覆盖节点本地进程间执行权，释放以确认终止/恢复完成为依据，不能以人工标终态替代。
3. **回滚期间丢失未托管编辑不能被评审自行批准。** A5 建议把操作内整文件恢复的数据丢失写为“已接受限制”，与 spec 的未托管字段保留要求冲突。本汇总不采纳该豁免；应增加冲突检测、受管字段恢复或显式拒绝，不能静默覆盖。
4. **两代内容可能相同。** 第二轮 V-M3 中“不同 generation 必然对应不同 digest”的全称判断与其 F6 的 A→B→A 反例矛盾：仅相邻有效变化需要不同摘要。保留 F6 的问题，舍弃等价约束论证；单表按 generation 唯一也可以正确表达历史，不强制新增表。
5. **规范化版本不能仅作诊断而不影响可比性。** 节点双侧投影是可选方案，但必须保证同一操作的双方按一致版本比较，并将快照身份与使用的规则版本关联；跨版本重放不能静默沿用旧判定。
6. **安全及保留策略中的新增建议不是既定需求。** token 熵数值、永久保留所有快照、不备份 CA、删除机器后仍允许旧证书连接、Unknown 目标允许人工跳过，均未获得原 spec 的明确授权或验收依据。不得由评审直接宣布“已接受”。普通资源级授权检查不等于引入完整 CRL/OCSP；旧证书本身与持有私钥的威胁情形也应分开。
7. **不能只按当前引用清理缓存。** 原报告建议节点清理未被当前快照引用的工件，需要同时保护上一成功状态、未决操作和约定回滚目标的引用，否则破坏恢复保证。

这些修正不要求第三次全面评审，也不改变原报告原文；本汇总明确标注采纳边界，供下一轮设计修订直接使用。
