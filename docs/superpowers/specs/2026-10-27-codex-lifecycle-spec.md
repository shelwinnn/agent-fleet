# Codex 生命周期纵向闭环规格

状态：待评审的子规格；尚未发布到 issue tracker。记录时间：2026-10-27 16:26:54 +0800。来源为《agent-fleet 原始需求纠偏设计》的 S1，以及本次确认的测试边界。Codex 是本子规格的明确选择；平台架构、受管用户、安装来源和方式仍需在真实环境中探测并验证。

## Problem Statement

操作者需要在多台主机的不同用户环境中维护 Codex。目前无法从界面完成安装、发现上游更新、升级和卸载并验证实际结果。配置一致不代表软件是最新版本；执行命令成功也不证明目标实例已达到预期。Windows 原生、macOS 和 Linux 的能力不能仅凭名称或模拟测试宣称完成。

现有 Codex 适配器在版本不匹配时报告安装器尚未接通，且其配置应用路径可能修改用户数据；现有期望状态渲染会省略未启用的 agent，不能把省略当作卸载意图。这些是本次代码核查事实，不代表完整链路已验收。

## Solution

操作者在一个界面选择主机、环境、用户和 Codex 安装实例，查看已安装版本与上游更新，预览并确认安装、升级或卸载。系统将版本固定为本次意图，复用现有控制面和节点通道执行，在目标环境重新发现并验证实际结果，逐目标展示成功、失败、未执行或未知。生命周期操作仅变更程序本体，保护用户数据。一个闭环覆盖 Windows 原生、macOS 和 Linux 的已验证组合。

## User Stories

1. 作为操作者，我希望查看接入主机，以便选择维护对象。
2. 作为操作者，我希望看到实际 OS、架构、用户和执行环境，以便避免操作错误环境。
3. 作为操作者，我希望区分 Windows 原生与 WSL，以便维护正确的安装实例。
4. 作为操作者，我希望看到每个 Codex 实例的路径、来源和版本，以便识别目标。
5. 作为操作者，我希望多实例时明确选择目标，以便其他实例不受影响。
6. 作为操作者，我希望知道 Codex 尚未安装，以便选择安装。
7. 作为操作者，我希望看到各平台与安装方式的支持或未验证状态，以便判断能否操作。
8. 作为操作者，我希望选择精确版本安装 Codex，以便获得可验证的结果。
9. 作为操作者，我希望在安装前看到目标和影响，以便确认操作。
10. 作为操作者，我希望知道缺失的运行时或权限，以便解决安装阻碍。
11. 作为操作者，我希望安装后看到实际版本和位置，以便确认程序可用。
12. 作为操作者，我希望手动检查上游更新，以便无需自行查找版本。
13. 作为操作者，我希望看到来源、渠道、可用版本和查询时间，以便判断更新信息是否适用。
14. 作为操作者，我希望查询失败时看到失败和缓存时间，以便不把未知误认作最新。
15. 作为操作者，我希望区分上游更新与期望状态偏差，以便理解各自含义。
16. 作为操作者，我希望选择一个固定版本升级多个目标，以便所有兼容目标执行相同意图。
17. 作为操作者，我希望提前看到不兼容目标，以便避免意外版本替换。
18. 作为操作者，我希望执行中出现新版本也不改变本次目标，以便确认与执行一致。
19. 作为操作者，我希望升级后核验实际版本，以便识别命令成功但升级失败的情况。
20. 作为操作者，我希望卸载前看到目标和数据保护范围，以便理解影响。
21. 作为操作者，我希望按已识别的安装来源卸载目标实例，以便保留其他实例。
22. 作为操作者，我希望未知来源时拒绝卸载并说明原因，以便避免误删。
23. 作为操作者，我希望停止管理时保留程序，以便不将停止管理误认为卸载。
24. 作为操作者，我希望安装、升级、卸载及失败恢复均保留配置、凭据、会话、skill 和项目，以便维护不破坏数据。
25. 作为操作者，我希望看到逐目标的执行状态和原因，以便定位部分失败。
26. 作为操作者，我希望提交前离线的目标标记为未执行且上线后不自动执行旧意图，以便控制变更时机。
27. 作为操作者，我希望结果丢失时显示未知并先核对实际状态，以便避免重复执行。
28. 作为操作者，我希望重复提交同一请求复用操作，以便避免重复变更。
29. 作为操作者，我希望只重试确定失败的目标，并关联原操作，以便保留成功结果和追溯记录。
30. 作为操作者，我希望重试前重新发现实际状态，并在影响变化时重新确认，以便避免执行过时意图。
31. 作为操作者，我希望页面用所选中英文说明实际状态、原因和下一步，以便完成维护。
32. 作为操作者，我希望操作记录包含目标、版本、时间和验证结果且不含秘密，以便追溯结果。
33. 作为操作者，我希望通过界面完成操作而无需编辑 profile JSON 或逐机手工安装，以便减少重复维护。

## Implementation Decisions

- 最小目标身份为主机、OS 环境、受管用户和明确安装实例；同一主机的 Windows 原生与 WSL 独立。首期为每个受管环境的一名用户和每个 agent 的一个明确实例，发现多个实例时必须选择。系统级安装或提权不默认执行。
- 复用机器台账、节点连接、持久操作、发布与结果存储；扩展现有期望状态，明确区分存在、缺席和停止管理，并保证生命周期操作不触发现有配置、MCP、rules 或 skill 收敛。不得通过省略快照隐式卸载。
- agent 管理优先 import agentmanager；接入前核查可导入接口、固定版本、许可证、平台和安装器副作用，并以编译与运行证据确认。若无法满足固定版本或数据保护要求，阻止该组合交付并另行决策，不擅自替换引擎。
- 上游版本发现独立于 drift，记录来源、渠道、适用平台、查询时间及失败；不假定版本均为 SemVer。安装和升级在创建操作时固定精确版本；不兼容目标明确展示，禁止静默替换。
- 操作前展示目标、版本、来源与影响并取得确认；同一已批准操作的重试不重复确认，影响变化时重新确认。每个目标执行后重新发现、验证版本或实例缺席；退出码单独不能判定成功。
- 程序操作仅允许必要的包文件和程序入口发生变化；不得改写、删除、迁移或重建 Codex 用户数据，也不得调用上游数据清理选项。验证安装器、探测与失败恢复的副作用；不满足要求则拒绝执行。
- 逐目标持久化状态和证据，至少区分成功、失败、未执行和未知。提交前离线不积压执行；结果丢失先核对，未知不计成功或自动重试；幂等键防止重复执行，仅允许重试确定失败目标。
- 页面支持用户任务所需的目标选择、检查更新、预览确认与结果查询；使用既定中英文和面向任务的文案原则。登录机制及视觉布局依独立规格处理，不在此推定实现细节。
- 每个 OS、架构、来源及安装方式组合分项记录能力和证据；未验证不标为支持。外部查询与执行应设超时及有限重试，错误明确上报。

## Testing Decisions

- 已确认的主要测试边界是浏览器发起操作至各目标实际结果的完整链路；断言用户可观察行为和结果，不绑定内部实现细节。利用可控版本源和故障注入覆盖固定版本、查询失败、部分失败、离线、结果丢失、去重和重试。
- 对高风险版本解析和数据保护补充较低层测试；覆盖安装、升级、卸载、探测及失败路径，比较用户数据目录内容、权限和链接，确认其他实例不受影响。
- Windows 原生、macOS、Linux 分别进行真机验收：发现、安装 V1、上游发现 V2、固定 V2 升级、停止管理、卸载，并验证目标用户可调用或目标实例确已消失。每种声明支持的 OS、架构和安装方式独立记录证据；容器与 loopback 不能替代真机。
- 现有 Codex 适配器、期望状态与部署控制器测试可作为测试结构参考，但现有测试通过不证明新生命周期能力或跨平台验收完成。
- 记录时间、控制面和节点版本、环境、来源、前后版本、操作标识、结果与验证证据，不记录敏感值。上述测试与验收均为待执行。

## Out of Scope

Skill 生命周期、其他 agent、任务执行、聊天同步、远程终端、用户管理、任意主机配置管理、无人值守自动升级、系统级安装与提权，以及认证细节和视觉布局设计。批量可靠性以本闭环所需行为为界，后续 S3 扩展到实际 NUC 和多台 VPS 的专项验收不由本规格单独宣称完成。

## Further Notes

本规格对应原设计 R1–R5、R7–R8 中适用部分及 A1–A5、A7–A8、A10、A14 中的 Codex 场景；不代表原设计全部验收完成。真实受管用户、平台架构、安装来源及 agentmanager 的可行性尚未验证。实现计划与生产操作须另行处理；本文不授权实际安装或卸载主机软件。
