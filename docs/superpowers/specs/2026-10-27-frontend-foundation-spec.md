# 前端基础：用户任务文案与中英文支持规格

状态：待评审的子规格，尚未发布到 issue tracker。记录时间：2026-10-27 16:33:48 +0800。依据《agent-fleet 原始需求纠偏设计》R9、R11、A11、A13 和本次确认的测试边界。本文不批准视觉布局方案或认证协议。

## Problem Statement

操作者使用 Fleet 管理主机和 agent 时，页面混合中英文，部分状态直接暴露内部实现、研发进度和原始错误，使人难以识别实际问题与下一步。用户需要在所选语言下理解当前对象、状态、操作影响及可采取的行动，同时准确看到失败、未知和真实限制。

现有 Profiles 页面混合英文表头、中文文案和 API、FR 等工程说明；已有页面渲染测试还断言部分工程说明。仓库使用 Svelte、TypeScript、Vite 和现有组件体系，已有 Vitest 渲染和状态测试，但这些证据不等同于完整浏览器语言切换验收。

## Solution

为现有产品页面建立集中管理的简体中文和英文消息资源，首次默认简体中文，允许用户切换语言；静态及动态界面、日期数量和无障碍文本随语言一致更新。按信息是否有助于用户完成任务进行页面文案评审，将内部说明和原始异常改写为准确、可行动的信息，保留有实际用途的技术信息和风险。此基础服务现有功能及后续生命周期页面。

## User Stories

1. 作为操作者，我希望首次打开页面时看到简体中文，以便直接理解界面。
2. 作为操作者，我希望切换到英文，以便按熟悉的语言操作。
3. 作为操作者，我希望切换语言后当前页面立即更新，以便无需重新开始操作。
4. 作为操作者，我希望导航和页面标题使用所选语言，以便找到功能。
5. 作为操作者，我希望按钮和表单标签使用所选语言，以便理解操作。
6. 作为操作者，我希望表单校验提示使用所选语言，以便修正输入。
7. 作为操作者，我希望确认弹窗说明实际对象和影响，以便做出决定。
8. 作为操作者，我希望空状态告诉我可做什么，以便继续任务。
9. 作为操作者，我希望加载和禁用状态说明实际原因，以便判断是否等待或采取行动。
10. 作为操作者，我希望失败提示说明发生了什么以及可采取的下一步，以便处理问题。
11. 作为操作者，我希望后端业务错误以所选语言呈现，以便理解错误。
12. 作为操作者，我希望离线和未知状态准确呈现，以便不把未知误认为成功。
13. 作为操作者，我希望看到操作限制和风险，以便做出知情选择。
14. 作为操作者，我希望实时消息和后续弹窗跟随当前语言，以便体验一致。
15. 作为操作者，我希望日期、相对时间和数量按当前语言格式显示，以便正确理解信息。
16. 作为使用辅助技术的操作者，我希望无障碍名称和提示也随语言切换，以便完成同样的操作。
17. 作为操作者，我希望页面不显示无助于任务的设计依据和交付说明，以便专注维护。
18. 作为操作者，我希望保留与任务相关的路径、版本、地址和操作标识，以便识别对象或定位失败。
19. 作为操作者，我希望用户输入、品牌和版本原样保留，以便内容不被错误翻译。
20. 作为操作者，我希望缺失翻译不会显示资源 key 或混杂另一种自然语言，以便可靠理解界面。
21. 作为操作者，我希望尚未交付的功能不伪装可用，以便不会误以为能完成操作。
22. 作为操作者，我希望可用功能因权限、离线或冲突被禁用时看到实际原因，以便决定下一步。
23. 作为维护者，我希望统一维护两种语言的消息，以便后续功能延续相同的体验。
24. 作为维护者，我希望检查页面文案的用户用途，以便识别例子之外的工程说明。
25. 作为维护者，我希望测试覆盖动态和异常状态，以便语言切换不会只影响静态导航。

## Implementation Decisions

- 使用现有前端技术栈和页面结构，引入集中管理的消息资源与语言状态，支持 `zh-CN` 和 `en`，首次默认 `zh-CN`；具体 i18n 库和语言偏好保存方式在实施设计中确定，不在此假定。
- 全部现有页面及其导航、按钮、表单、校验、确认、空态、加载态、禁用态、通知、实时消息、业务错误和无障碍标签纳入范围；切换语言时当前可见状态和之后产生的动态内容都使用当前语言。
- 日期、相对时间、数字和数量遵循所选 locale；品牌、版本、用户数据、来源地址及操作标识保持原值。两种语言应完整覆盖，交付不得显示裸 key 或混杂自然语言。
- 以信息用途评审正文、侧栏、卡片、tooltip、弹窗和辅助技术文本：保留能够识别对象、理解状态和影响或完成下一步的信息；移除或改写无助于用户任务的内部 schema、设计依据、协议细节、研发占位、调试输出和交付说明。举例是非穷尽的，不建立关键词黑名单。
- 面向用户的错误应表达实际发生的情况与可采取的行动；后端业务错误映射为本地化文案。未知原因采用准确的通用说明，不臆造原因、不直接展示堆栈或原始异常作为默认提示；有定位价值的操作标识可保留。
- 不隐藏真实限制、失败或风险，不将未知、跳过或阻塞改写成成功；尚未交付的功能不作为可用入口呈现。已有功能因离线、权限、安装方式或冲突不可用时解释实际原因。
- 保持现有业务动作、鉴权和状态语义；涉及删除旧工程说明的测试应改为断言用户可观察的正确含义，而非保留旧文案或用固定关键词扫描替代语义评审。

## Testing Decisions

- 已确认以浏览器中现有页面的用户可见行为作为主要测试边界：验证首次语言、切换及当前页面、后续弹窗、实时消息、错误、空态和无障碍文本，断言实际行为而非资源组织方式。
- 使用代表性状态和可控后端响应验证失败、离线、未知、禁用及动态数据；检查用户数据、品牌、版本和用于任务的技术信息原样保留。对日期、数量和错误映射等高风险规则补充测试。
- 对中英文所有可见状态进行人工语义评审：逐项判断其是否帮助识别对象、理解实际状态和影响或完成下一步；同时检查未列举的工程说明及确有任务价值的路径、地址和标识。关键词扫描不能替代评审。
- 现有 Vitest 页面渲染与状态测试可作为先例；它们包含对旧工程文案的断言，也不能证明浏览器交互、语言切换或无障碍行为。需要覆盖这些新增行为，不把既有测试结果视为验收通过。
- 完成条件：两种语言覆盖所有现有可见状态，无裸 key 或混杂自然语言；动态时间、数量、错误及无障碍文本一致；用户任务文案评审通过，且真实失败和风险未被掩盖。上述测试和评审均待执行。

## Out of Scope

登录、退出及其凭据、token、服务端会话语义；用户管理；视觉风格、布局、配色和导航重构；Codex、skill 或批量生命周期功能的后端实现；新增语言。认证按独立规格推进，视觉布局另行确认；本规格不将当前管理令牌流程视为最终登录设计。

## Further Notes

本规格为前端基础，不替代原设计 A12 的认证验收或 A14 的生命周期操作验收。后续页面也应遵守本规格；现有依赖的具体 i18n 选择和语言偏好持久化方式尚未定案。实现计划、依赖安装和产品代码修改不由本文自动授权。
